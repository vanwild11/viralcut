## Почему ViralCut

- **Всё локально.** Видео, звук и текст не отправляются на серверы: Whisper, ffmpeg и
  OpenCV работают на вашем компьютере. Нет аккаунтов, API-ключей и подписок.
- **Один запуск — пачка клипов.** До 50 вертикальных роликов с хуком, субтитрами и
  умным кадрированием по лицу.
- **Прямой эфир — на лету.** Клипы появляются, пока стрим ещё идёт; готовый клип можно
  перерендерить из записи.
- **Субтитры, которые читают.** Караоке-подсветка, спокойный темп, 24 шрифта и загрузка
  своих TTF/OTF.
- **Без сюрпризов.** Понятные статусы, повтор упавшей обработки и видимый откат качества.

## Возможности

- **Источники**: YouTube (до 1080p), Twitch (VOD и клипы), TikTok, Instagram, VK, X, прямые ссылки на mp4/m3u8.
  Для Twitter/X выбирается прямой HTTPS-файл (без медленной склейки HLS), вертикальные видео не теряют качество.
  а также загрузка файла с диска. Для закрытых площадок — cookies из браузера.
- **Качество YouTube**: по умолчанию 1080p. Видео и звук скачиваются отдельно и
  объединяются FFmpeg без перекодирования. Если 1080p недоступно или заблокировано,
  интерфейс показывает причину и кнопку «Повторить в 1080p», а факт отката на 360p виден.
  В приложение встроен PO-token провайдер, без него YouTube отдаёт только 360p.
- **Скорость распознавания**: жадное декодирование (`beam_size=1`), Apple Metal (MPS) с
  автоматическим откатом на CPU, обновление этапа каждые 5 секунд — видно, что процесс жив.
  Рендер 1080p идёт в `veryfast`, это заметно быстрее при том же качестве для соцсетей.
- **Распознавание речи**: локальный `faster-whisper` (small по умолчанию) с таймингами
  отдельных слов. Длинные видео обрабатываются частями по 15 минут: прогресс не замирает,
  а при сбое VAD приложение автоматически повторяет часть без фильтра тишины. Если модель недоступна — резервный путь через субтитры источника.
- **Поиск вирусных моментов**: оценка по хуку в первых секундах, плотности речи, паузам,
  громкости, эмоциональной лексике, конкретике (цифры/деньги), завершённости мысли и
  оптимальной длине. Пересекающиеся и повторяющиеся фрагменты отбрасываются.
- **Вертикаль**: 9:16 / 1:1 / 16:9. Кадрирование:
  - «умный кроп» — находит лицо (YuNet), плавно ведёт его и заполняет вертикальный кадр;
  - «размытый фон» — весь кадр виден, сверху и снизу размытая подложка;
  - «по центру» — статичный центральный кроп.
  Если лиц в кадре почти нет (скринкаст, слайды), умный кроп автоматически откатывается
  к размытому фону, чтобы не обрезать текст.
- **Субтитры**: ASS с подсветкой текущего слова и хуком. Настраиваются:
  - **шрифт** — 24 варианта: Montserrat, Inter Black, Manrope, Roboto Condensed, Lato Black, PT Sans Narrow, Oswald, Rubik, Exo 2, Unbounded, Russo One, Play, Philosopher, Yeseva One, Comfortaa, Caveat, Golos Text, Onest, Marmelad, Bad Script, Marck Script, Ruslan Display, Stalinist One, Underdog
    (все с кириллицей);
  - **размер** — 70–180 (одинаковая визуальная высота у разных шрифтов);
  - **положение** — снизу, по центру, сверху + сдвиг −120…+180;
  - цвет подсветки, КАПС, показ хука.
- **Контроль скорости**: если загрузка «залипает» ниже 45 КБ/с дольше 45 секунд,
  приложение автоматически переподключается к источнику и продолжает с места обрыва.
  Любую загрузку можно отменить кнопкой и запустить заново.
- **Проверка перед скачиванием**: после вставки ссылки приложение показывает длительность,
  доступные качества и размер файла (1080p / 720p / 360p), рекомендует качество под длину
  ролика. Для двухчасового видео 1080p — это ~1.6 ГБ, 360p — ~330 МБ, поэтому для длинных
  записей рекомендуется 360p: скачивается в разы быстрее.
- **До 50 нарезок** за один запуск (5, 10, 20, 30, 50 или все найденные).
- **«Вырезать паузы»**: тишина и «эээ…» между мыслями убираются склейкой до
  рендера — клип становится плотнее, а слова, субтитры и умный кроп
  пересчитываются на новую шкалу времени. Опция есть на главной и в редакторе.
- **Реакции аудитории и монтаж**: смех и аплодисменты находятся по звуку, а
  смены сцен — по кадрам (OpenCV); моменты с реакцией получают балл, а границы
  клипов притягиваются к монтажной склейке. Без numpy/OpenCV всё работает как
  раньше — сигналы просто не учитываются.
- **Экономный режим**: для длинных видео можно не скачивать весь ролик. Приложение качает
  только аудио (~30–100 МБ на пару часов), распознаёт речь, находит моменты, показывает
  предпросмотр первого и скачивает видео лишь для выбранных фрагментов. Для двухчасового
  1080p-видео это обычно 5–20 раз меньше трафика, чем полный файл. Включается галочкой
  «Экономно» в окне выбора качества; для видео длиннее 10 минут она включена по умолчанию.
- **Окно настройки перед нарезкой**: после вставки ссылки видео скачивается, открывается
  отдельное окно с плеером и живым примером субтитров. Можно выбрать шаблон (TikTok,
  Reels, «Мягкий», «Классика», «Спорт», «Дерзкий», «Рукописный», CapCut, «Мем», «Неон», «Бьюти», «Кисть», «Скрипт»), шрифт, размер, цвет, положение и сдвиг, посмотреть, как это
  выглядит на кадре, и только потом запустить нарезку.
- **Редактор клипа**: границы, хук, подпись, формат, цвет, включение субтитров, перерендер.
- **Экспорт**: по одному MP4 или всё сразу ZIP. Подпись с хештегами — в один клик.
- **Повторный запуск**: если обработка упала (например, сайт потребовал авторизацию), кнопка
  «Повторить обработку» перезапускает проект без потери настроек.
- **Локально и без API-ключей**: SQLite + файлы в `data/`.

- **Правка текста субтитров** прямо в редакторе клипа: исправили имя бренда или
  термин — клип перерендерился, тайминги сохранились.
- **Экспорт SRT** кнопкой рядом со скачиванием: субтитры клипа (с вашими
  правками) для Premiere, Resolve и CapCut.

## Обновления

Приложение само узнаёт о новых релизах: раз в 6 часов — один запрос
`GET https://api.github.com/repos/vanwild11/viralcut/releases/latest`
(таймаут 5 с, кеш в `data/update.json`). Если версия новее, в сайдбаре над
Telegram появляется карточка «Доступна версия X» — она открывает страницу
релиза в браузере, откуда скачивается архив под вашу платформу.

Наружу уходит только версия приложения в User-Agent: видео, пути и настройки
не отправляются. Проверку можно выключить — переменной окружения
`VIRALCUT_UPDATE_CHECK=0` или запросом
`POST /api/update/settings {"enabled": false}`; интервал меняется
`VIRALCUT_UPDATE_TTL` (в секундах). Черновики и пререлизы игнорируются.

## Скорость

Обработка идёт локально и параллельно там, где это можно:

| Этап | Что делаем |
|---|---|
| Распознавание | пачечное декодирование (faster-whisper), ~0.25× от длительности записи |
| Поиск моментов | эвристики по речи, паузам и громкости, без внешних API |
| Рендер | 2–3 клипа параллельно, аппаратный энкодер videotoolbox / nvenc / qsv |

Замер на 6-минутном видео: **231 секунда** целиком (было 542), WER субтитров
**4.7%**. Настройки: `VIRALCUT_RENDER_WORKERS` (число параллельных рендеров),
`VIRALCUT_HW_ENCODE=0` (выключить аппаратный энкодер),
`VIRALCUT_WHISPER_BATCH=0` (вернуть последовательное распознавание),
`VIRALCUT_HW_ENCODE=0` (не использовать аппаратный энкодер). Аппаратный энкодер
проверяется пробным кадром при старте: если железо не поддерживает
videotoolbox/nvenc/qsv, рендер молча идёт на libx264.

### Ограничение ресурсов

Рендер не забирает весь компьютер:

| Ограничение | По умолчанию | Переменная |
|---|---|---|
| Параллельных рендеров | 2 (на 8 ядрах) | `VIRALCUT_RENDER_WORKERS` |
| Потоков на один ffmpeg | 3 | `VIRALCUT_FFMPEG_THREADS` |
| Приоритет процессов | `nice 10` / BELOW_NORMAL | `VIRALCUT_NICE`, `VIRALCUT_LOW_PRIORITY=0` |
| Потоков распознавания | половина ядер | `VIRALCUT_WHISPER_THREADS` |
| Энкодер | GPU (videotoolbox / nvenc / qsv) | `VIRALCUT_HW_ENCODE=0` — вернуть CPU |

Текущие значения видны в `/api/health` в полях `limits` и `hw`.

### macOS

#### Готовое приложение

Скачайте [`ViralCut-1.5.8-macOS-arm64.zip`](https://github.com/vanwild11/viralcut/releases/latest/download/ViralCut-1.5.8-macOS-arm64.zip) из раздела **Releases** (≈620 МБ; внутри модели и все зависимости, после установки ничего не докачивается).

1. Распакуйте и перетащите `ViralCut.app` в «Программы».
2. Запустите — откроется своё окно, браузер не нужен.
3. Если macOS не даёт открыть приложение:
   ```bash
   xattr -dr com.apple.quarantine /Applications/ViralCut.app
   ```
   или правый клик → «Открыть».

Требования: Apple Silicon (M1/M2/M3/M4), macOS 11+, ~1,5 ГБ на диске.
Данные лежат в `~/Library/Application Support/ViralCut`, готовые файлы — в `~/Downloads/ViralCut`.

Собрать заново из исходников:

```bash
./build_app.sh     # dist/ViralCut.app
```

Приложение подписано ad-hoc, без нотаризации Apple.

### Браузерная версия (любая ОС)

```bash
./run.sh
```

Откройте <http://127.0.0.1:8765>.

Первый запуск создаст окружение и поставит зависимости. Для веб-версии модель Whisper
нужно положить в `data/models` или указать `VIRALCUT_WHISPER_DIR`; в готовом `.app` она
уже входит в сборку.

Требования для запуска из исходников: Python 3.12+ и macOS / Windows / Linux. ffmpeg подтягивается автоматически через
`imageio-ffmpeg` (статическая сборка с libass и libx264), отдельно ставить не нужно.

### Настройки через переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `VIRALCUT_PORT` | `8765` | порт |
| `VIRALCUT_DATA` | `./data` | папка для проектов, моделей и БД |
| `VIRALCUT_WHISPER` | `small` | `base` / `small` / `medium` / `large-v3` |
| `VIRALCUT_COMPUTE` | `int8` | `int8` / `float16` / `float32` |
| `VIRALCUT_DEVICE` | `cpu` | `cpu` / `mps` (экспериментально) |
| `VIRALCUT_WORKERS` | `1` | сколько проектов обрабатывать параллельно |

## Как это работает

```
ссылка/файл
   │  yt-dlp
   ▼
source.mp4 ──► faster-whisper ──► слова с таймингами
   │                                   │
   │                            анализ моментов
   │                                   │
   └────────► ffmpeg ◄───────────  клипы + ASS
                 │
                 ▼
        1080×1920 MP4, AAC 192k, -14 LUFS
```

1. **Загрузка** — `yt-dlp` с выбором формата до 1080p и склейкой в mp4.
2. **Транскрипция** — Whisper с VAD и word-timestamps; предложения собираются по
   пунктуации и паузам.
3. **Анализ** — для каждого предложения строится окно 15–60 с; окно оценивается по
   семи текстовым/звуковым факторам плюс реакции аудитории (смех, аплодисменты) и
   смены сцен; лучшие отбираются с подавлением пересечений и текстовых дублей.
4. **Рендер** — вырезается точный фрагмент, собирается вертикальный кадр, вшиваются
   субтитры, звук нормализуется по громкости, файл получает faststart.

## Структура

```
viralcut/
  main.py        FastAPI: API и статика
  pipeline.py    оркестрация обработки проекта
  downloader.py  yt-dlp и прямые ссылки
  transcribe.py  faster-whisper + резервные субтитры
  analyze.py     поиск моментов и скоринг
  subtitles.py   генерация ASS
  render.py      ffmpeg: кадрирование, субтитры, звук
  db.py          SQLite
  jobs.py        фоновые очереди
web/             интерфейс (без сборки)
assets/fonts/    Montserrat для субтитров
data/            проекты, клипы, модель, БД (в .gitignore)
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/projects` | `{url, options}` → проект |
| `POST` | `/api/upload` | файл multipart → проект |
| `GET` | `/api/projects` | список проектов |
| `GET` | `/api/projects/{id}` | проект + клипы |
| `DELETE` | `/api/projects/{id}` | удалить проект и файлы |
| `POST` | `/api/clips/{id}/rerender` | изменить границы/хук/стиль и перерендерить |

| `GET` | `/api/system` | нагрузка CPU/RAM/GPU для виджета |
| `GET` | `/api/diagnostics` | разбор app.log: падение, этап, ошибки |

## Проверка качества (реальный ролик)

Проверено на YouTube-ролике с доступным 1080p:

| Параметр | Значение |
|---|---|
| Выбранный формат | `137+140` — H.264 1080p + AAC 128k |
| Источник по ffprobe | 1920×1080, H.264, 29.97 fps |
| Готовая нарезка | 1080×1920, H.264, 30 fps |
| Превью | 540×960 (лёгкая копия для интерфейса) |
| Скачивание | 6.8 МБ за 0.9 с (3.3 МБ/с в тестовой сети) |
| Склейка дорожек | FFmpeg remux, без перекодирования видео |
| Весь проект | 65 с (скачивание + Whisper + рендер) |

До исправления терялось именно на скачивании: старый yt-dlp на Python 3.9 не мог получить
PO-token и брал единственный доступный формат 18 (360p). Превью и экспорт качество не теряли.

## Свои шрифты

В блоке «Стиль субтитров» рядом с выбором шрифта есть кнопка **＋**. Она принимает TTF или
OTF до 30 МБ, сохраняет файл в `~/Library/Application Support/ViralCut/fonts` и сразу
добавляет шрифт в список (группа «Мои шрифты») — в главном окне, окне шаблона и редакторе.
Шрифт работает и в предпросмотре, и в финальном рендере через libass. Если в файле нет
кириллицы, приложение предупредит: русские буквы могут подставиться системным шрифтом.

## Экономный режим: без полного скачивания

Схема: ссылка → выбор качества и галочка «Экономно» → скачивается только аудио → Whisper
распознаёт речь → приложение находит моменты → показывает окно шаблона с предпросмотром
первого момента → после подтверждения скачиваются только выбранные фрагменты видео и
рендерятся клипы. Полный исходник на диск не попадает.

Звук в клипах нормализуется в два прохода (linear loudnorm, −14 LUFS) и получает короткие
фейды на стыках, чтобы не было щелчков и «качелей» громкости. Если аудиодорожка недоступна
отдельно, приложение скачивает лёгкий 360p-файл и берёт звук из него.

Ограничение: у клипов, собранных в экономном режиме, нельзя потом двигать границы в
редакторе — шаблон выбирается до запуска. Обычный режим (без галочки) даёт полный исходник
и полный редактор.

## Где лежат готовые нарезки

```
~/Library/Application Support/ViralCut/projects/<id>/clips/clip_01.mp4
```

В приложении кнопка **«MP4»** сохраняет клип в `~/Downloads/ViralCut` и сразу показывает его
в Finder. **«Скачать всё»** сохраняет ZIP туда же, **«Открыть папку»** открывает папку с
клипами проекта. В браузерной версии те же кнопки работают как обычное скачивание.

## Приватность и перенос на другой Mac

Всё считается локально: скачивание, Whisper, анализ, ffmpeg, субтитры и рендер. Наружу уходят
только запросы к самому источнику видео (YouTube и т.п.), за моделями HuggingFace при первом
запуске и за JS-солвером YouTube (маленький файл). Ни аналитики, ни аккаунтов, ни нашего
сервера нет. PO-token провайдер слушает только `127.0.0.1`.

Данные лежат в `~/Library/Application Support/ViralCut`: проекты, исходники, клипы, модель,
кэш. Другой Mac их не видит — история не синхронизируется. Переносить проекты можно,
скопировав эту папку целиком (это много гигабайт).

Приложение собрано под Apple Silicon (arm64), macOS 11+. На Intel не запустится. Подпись
ad-hoc, без нотаризации: при переносе архивом может понадобиться правый клик → «Открыть»
или `xattr -dr com.apple.quarantine /Applications/ViralCut.app`. Модель (~460 МБ) на новом
Mac скачается заново при первом видео, cookies браузера не переносятся.

## Если приложение закрылось само (app.log)

Настольная версия пишет журнал в папку данных:
Windows — `%APPDATA%\ViralCut\app.log`, macOS — `~/Library/Application Support/ViralCut/app.log`.

- `faulthandler` включён всегда: при нативном падении в лог попадает дамп стека
  (`Fatal Python error`, `Thread 0x…`), а не только «окно исчезло».
- Неперехваченные исключения главного потока и фоновых потоков тоже пишутся в лог,
  в начале запуска ставится маркер `=== ViralCut start … ===`, при штатном
  закрытии — `=== ViralCut stop … ===`. Нет маркера stop → запуск был аварийным.
- Этапы обработки (`[stage] Рендер: 3 из 10 готово`, `[api] Пересборка…`) дают
  понять, на чём именно упало.
- Разбор: в настройках приложения кнопка **«Разобрать журнал»** (эндпоинт
  `GET /api/diagnostics`) или из консоли:

```bash
python -m viralcut.diagnostics                    # найдёт лог сам
python -m viralcut.diagnostics path/app.log --tail 80
```

Отчёт покажет число запусков, аварийное завершение, последний этап, трейсбеки и
короткий вердикт. Лог ротируется после 8 МБ (старый — `app.log.1`).

## Ограничения

- YouTube отдаёт HD-форматы только с авторизацией: приложение автоматически пробует HD
  (android_vr), а если YouTube отвечает 403 — скачивает SD 360p и продолжает работу.
  Для HD включите «Cookies из браузера» (Chrome/Safari) в настройках проекта.
  Приватные и платные видео недоступны.
- Instagram/TikTok часто тоже требуют cookies — без них часть ссылок не открывается.
- Скоринг «вирусности» — эвристика, а не гарантия просмотров. Хук и границы лучше
  проверять глазами в редакторе.
- Рендер идёт на CPU: примерно 0,6× от длительности клипа на Apple Silicon (3-минутное
  видео целиком — около 2,5 минут вместе с распознаванием).
- Скачивайте и монетизируйте только тот контент, на который у вас есть права.

## Рекомендации YouTube

На главном экране нажмите **«Найти видео на YouTube»**. Выберите русскоязычную
или англоязычную подборку, тему и при желании собственный запрос на нужном языке.
API-ключ не требуется. Поиск через yt-dlp получает только метаданные 40 результатов;
показываются до 12 подходящих видео. Карточка открывается на YouTube для просмотра,
а «Выбрать для нарезки» открывает подтверждение качества и размера перед загрузкой.

Подборка исключает дубликаты, текущие и запланированные эфиры, видео короче
4 минут и длиннее 4 часов. Язык предположен по преобладанию кириллицы или латиницы
в заголовке: это не проверка языка речи или демографии зрителей. Просмотры —
публичные общие счётчики, а не просмотры выбранной аудитории. Это подборка среди
результатов поиска, не полный рейтинг YouTube и не список текущих трендов.

Порядок «Больше просмотров» сортирует по общему числу просмотров. «Для нарезки»
использует log10(просмотры + 1) и добавляет 2 балла видео длительностью 10–120 минут.
Содержание и достоверность ролика этим поиском не анализируются; неизвестные
просмотры явно отмечены. Результаты кешируются в памяти на 15 минут.
При ошибке сети приложение предлагает повторить поиск, не запуская загрузку.

## Дополнительный видеоряд, логотип и реклама

Основа этой рабочей версии — официальный тег **v1.5.8**. На главной нажмите
**«Игра, логотип и реклама»**, настройте композицию и сохраните перед созданием
проекта. Для готового проекта та же кнопка под клипами сохраняет настройки и
пересобирает все готовые клипы из исходников. Отключение флажка убирает эффект
при следующей пересборке. Настройки существующего проекта сохраняются в его options.

- **Игра**: свой файл до 200 МБ / 10 минут либо подбор YouTube: Minecraft Parkour,
  Subway Surfers, Trackmania. Автовыбор предлагает Minecraft как непрерывный фон;
  это простой пресет, содержание основного ролика не анализируется. YouTube-файл
  скачивается только после нажатия кнопки скачивания: до 3 минут из середины записи в 720p.
  Выберите запись с разрешением на использование. Игра сверху или снизу занимает
  половину кадра, повторяется до конца основного видео; её звук не используется.
- **Логотип**: PNG, JPEG или WebP, прозрачность PNG сохраняется. Четыре угла,
  размер от 5 до 30% ширины кадра. Логотип накладывается и на рекламную вставку.
- **Реклама**: своё видео до 200 МБ, длительностью 1–120 секунд. Автомонтаж ищет
  конец паузы не менее 250 мс в диапазоне 25–75% длительности готового клипа,
  выбирает ближайшую к середине. Если пауз нет, вставляет в середину. Это анализ
  тишины, не понимание смысла. В карточке результата указан момент и способ выбора.
  Основное видео после рекламы продолжается без пропуска; немая реклама получает
  тихую аудиодорожку. Субтитры основного видео уже встроены и останавливаются на рекламе.

Файлы хранятся в `data/composition` (или папке данных desktop-сборки). Автомонтаж
выполняется после основного рендера и вырезания пауз, до превью и экспорта, поэтому
композиция попадает в MP4 и ZIP. Дополнительное кодирование увеличивает время рендера.
Экспорт SRT по-прежнему описывает исходный фрагмент без временного сдвига рекламы;
для файла с рекламой используйте встроенные субтитры.


### Исправленная компоновка игрового режима

Основное видео рендерится сразу в область 60% высоты, игра занимает 40%:
портретный клип больше не уменьшается с чёрными полями. Субтитры рассчитываются
для основной области. Игровой файл анализируется по распределённому движению,
чтобы пропустить статичное меню; выбранный участок можно просмотреть и изменить
начало вручную. Анализ движения не гарантирует распознавания меню.

По умолчанию каждая нарезка получает собственную точку старта внутри игрового
участка. Она закреплена за номером клипа: повторная сборка сохраняет выбор.
Короткие игровые записи повторяются, участки разных нарезок могут пересекаться.
В окне композиции это отключается флажком «Разный игровой участок».
Новые записи с YouTube берутся из середины исходника (до 3 минут), а не из заставки в начале.
У логотипа есть опция удаления однотонного фона, прозрачные поля обрезаются;
для точного результата рекомендуется прозрачный PNG.

## Публикация в YouTube

У готового клипа нажмите **«На YouTube»**. Откроется предпросмотр, название,
описание, доступ, обязательный выбор аудитории и переключатели отметок
изменённого контента, платной интеграции и публикации по расписанию.
По умолчанию доступ **личный**. Отправка начинается только после нажатия
**«Загрузить на YouTube»**. Для расписания файл загружается сейчас как личный,
а YouTube открывает его в выбранное время. Классификацию Shorts определяет YouTube.

### Подключение канала один раз

1. В Google Cloud создайте проект, включите **YouTube Data API v3**.
2. Настройте **OAuth consent screen**. Для режима Testing добавьте свой аккаунт
   в **Test users** (в этом режиме Google может ограничивать срок refresh token).
3. Создайте OAuth client ID типа **Desktop app**, скачайте JSON.
4. В ViralCut откройте **Настройки → YouTube → Выбрать OAuth-файл**, затем
   **«Подключить канал»** и подтвердите разрешения в системном браузере Google.

Используются `youtube.upload` для отправки и `youtube.readonly` для отображения
подключённого канала. Пароль Google в ViralCut не вводится. Desktop OAuth использует
loopback callback на случайном локальном порту, state и PKCE. Токены хранятся
в системном vault через keyring (Keychain macOS / Windows Credential Manager),
никогда в settings.json и никогда не отдаются веб-интерфейсу. При недоступности
vault подключение не сохраняется в открытом виде. OAuth client JSON лежит
в папке данных `youtube/client.json` с правами только владельцу на POSIX.

Загрузки идут по одной в фоновой очереди через официальный клиент Google с
resumable upload и повтором сетевых запросов. Перед отправкой создаётся временная
копия MP4, чтобы пересборка клипа не меняла отправляемый файл. Повторный клик по
неизменённому готовому/загружаемому клипу возвращает существующую загрузку.
Можно отменить очередь или загрузку между порциями; если сервер уже принял видео,
результат показывается как загруженный. После сбоя приложения незавершённые
загрузки не отправляются повторно автоматически: сначала проверьте YouTube Studio.
Сохранённая история доступна при повторном открытии окна публикации.

«Отключить» отзывает разрешение в Google и удаляет локальные токены. Если сеть
недоступна, токены удаляются локально, а интерфейс объясняет, что доступ надо
отозвать в настройках Google. Реальная отправка требует настроенного OAuth-проекта,
подключённого канала и доступной квоты YouTube API.
